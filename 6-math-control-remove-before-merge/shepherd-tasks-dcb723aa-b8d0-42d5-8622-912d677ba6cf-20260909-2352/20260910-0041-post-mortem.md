## Section 7: Failure Analysis and Recovered Incidents

The campaign had no terminal task failure, merge failure, or unresolved review failure. The following recoverable incidents increased operational noise:

### 7.1 Stage 30 environment and query friction on [#7](https://github.com/edburns/dd-3061974-01-bash/issues/7)

An early PR-invariant probe exited nonzero and was followed by a diagnostic pass. Local validation also initially exited `127` because `pwsh` was unavailable in that shell, and two CLI query forms were incompatible with the installed tooling. The shepherd treated the missing executable as an environment failure rather than a product-test failure, corrected the invocation/query path, and ultimately recorded 9/9 passing tests at the validated stage-30 HEAD.

**Recommendation:** Add a stage-30 preflight that checks `pwsh`, `jq`, required `gh` JSON fields, and repository runner availability before assignment. This should produce one explicit environment diagnostic rather than interleaving tool-compatibility recovery with acceptance validation.

### 7.2 Intermediate local test failures while fixing [#9](https://github.com/edburns/dd-3061974-01-bash/pull/9)

The first exact-output refactor temporarily produced 7 passed/4 failed tests; a subsequent correction produced 10 passed/1 failed. These were local implementation iterations, not failures on the merged HEAD. The final correction passed 11/11 tests, CI passed, and CCRA approved the exact reviewed HEAD.

**Root cause:** Process-output collection semantics changed while fixing path-safe argument handling, exposing a mismatch between scalar/array behavior and exact line counting.

**Recommendation:** Keep a reusable, separately tested child-process capture helper for PowerShell CLI contract tests. It should preserve interior empty records, remove only the normal terminal split artifact, and pass arguments through `ProcessStartInfo.ArgumentList`.

### 7.3 Final-gate `jq` syntax error on [#10](https://github.com/edburns/dd-3061974-01-bash/pull/10)

The first final-gate command had an unmatched parenthesis in its `jq` predicate and exited `3`. All preceding remote checks had passed and no repository state changed. The shepherd corrected and reran the predicate, producing:

`FINAL_GATES_OK ... comments=0 unresolved=0 bad_checks=0 base=experiment/shepherd-control mergeable=MERGEABLE`

**Recommendation:** Move complex `jq` predicates into versioned, shell-tested helpers or run `jq -n` syntax validation before using them in a state-changing merge path.

## Section 8: Observations and Recommendations

### 8.1 What worked well

- **Serial dependency handling was correct.** [#8](https://github.com/edburns/dd-3061974-01-bash/issues/8) did not begin until [#9](https://github.com/edburns/dd-3061974-01-bash/pull/9) had merged into the base branch.
- **Current-HEAD gates were consistently enforced.** Both PRs were checked for linkage, base, nonempty diff, successful workflows, review state, unresolved threads, and stable HEAD before merge.
- **CCRA materially improved correctness.** Its [#9](https://github.com/edburns/dd-3061974-01-bash/pull/9) findings covered path portability, exact large-integer behavior, negative-result rejection, and exact stdout shape.
- **Convergence was complete.** All four findings were resolved, the final reviewed heads had zero actionable comments, and both PRs merged with green checks.
- **Control treatment remained intact.** Lesson propagation was `off`; `campaign-lessons.md` remained unchanged with no validated lessons.

### 8.2 What could improve

- **Preflight reliability:** Missing `pwsh` and incompatible query assumptions should be detected before acceptance work begins.
- **Script maintainability:** Large inline shell and `jq` expressions made simple syntax errors possible in critical gates.
- **Metrics observability:** Token fields were present but redacted, preventing cost-normalized comparison with other campaign treatments.
- **Phase handoff overhead:** 11m 52s, about 24% of campaign wall time, occurred outside recorded phase sessions.

### 8.3 Actionable recommendations

1. Add a campaign preflight that validates `pwsh`, Pester 5.7.1 availability, `gh` feature support, `jq` syntax support, repository runner presence, remote identity, and base-branch existence.
2. Extract stage-40 review and merge predicates into versioned helpers with fixture-based shell tests, especially current-HEAD review selection and status-check exemptions.
3. Standardize the isolated PowerShell process helper proven by [#9](https://github.com/edburns/dd-3061974-01-bash/pull/9), including paths with spaces and exact blank-line behavior.
4. Emit a compact machine-readable phase summary alongside each Markdown export with start/end timestamps, PR, review IDs, finding counts, test totals, merge commit, and terminal status.
5. Preserve numeric token and credit totals in a privacy-safe aggregate artifact when policy permits; otherwise record an explicit `redacted` availability state so post-mortems need not infer it.
6. Record handoff timestamps in the run manifest to separate orchestration latency, remote-agent wait time, and local execution time.

### 8.4 Control-campaign interpretation

This run is a valid `LESSON_PROPAGATION=off` control observation: 100% completion, four findings across four reviews, and 49m 29s wall clock for two serial tasks. Comparisons with treatment campaigns should use the same task count and complexity, distinguish active phase time from total campaign time, and avoid attributing [#8](https://github.com/edburns/dd-3061974-01-bash/issues/8)'s clean first review to lesson propagation. Its most direct inherited advantage was the already-merged implementation and test hardening from [#7](https://github.com/edburns/dd-3061974-01-bash/issues/7).
